## Why

This violation type is catalogued but has no guide of its own, so the specific remediation advice
that would normally appear here does not exist yet. The occurrences below are real; only the
tailored guidance is missing.

## Corrective move

Start from the rule's own message and ask what it is protecting against — the rule exists because
something went wrong before. Then find the fix that reduces the underlying risk rather than the one
that clears the report: fewer moving parts, a failure that stays visible, a name that says what the
thing is.

## Expected outcome

The occurrence is gone because the code or prose changed for a reason you could state to a reviewer,
and a guide for this type is worth writing once you have stated it.

## Avoid

Any change designed to satisfy the detector while leaving the underlying problem in place. A
suppression comment, a narrowed pattern, or a reworded sentence that keeps the same claim all clear
the report and preserve the defect.
